Kelas generik

Buat kelas yang dapat dipakai dengan berbagai tipe tanpa casting manual saat membaca nilai.

Pertemuan 11
KonsepSimulasiKuisPraktik

0/2 jawaban benar

Konsep inti

Motivasi

Kelas berbasis Object dapat menyimpan beragam nilai, tetapi pemanggil perlu casting dan dapat mengalami ClassCastException. Generics memindahkan banyak pemeriksaan tipe ke kompilasi.

Parameter dan argumen tipe

Box<T> mendeklarasikan parameter T; Box<String> memilih String sebagai argumen tipe. new Box<>() memakai inferensi. Gunakan Integer, bukan int, sebagai argumen tipe.

Konvensi nama

T sering berarti Type, E Element, K Key, V Value. Nama itu konvensi, bukan aturan sintaks. Hindari raw type karena melemahkan pemeriksaan tipe.

Studi kasus kedai kopi

Pesanan<T> dapat menyimpan produk dengan tipe berbeda tanpa menggandakan kelas wadah. Jika operasi membutuhkan properti umum, pertimbangkan batas seperti T extends Produk.

Prediksi hasil

Pilih skenario dan tebak hasilnya sebelum membuka pembahasan. Potongan kode Java menampilkan hasil yang diharapkan, tanpa menjalankan Java di browser.

Box<String> b = new Box<>();
b.set("Kopi");
String isi = b.get();
Hasil
Kompilasi berhasil; isi = Kopi

T digantikan String untuk pemeriksaan tipe.

Box<String> b = new Box<>();
b.set(42);
Hasil
Galat kompilasi

Nilai int yang di-box menjadi Integer tidak cocok dengan String.

Box<Integer> b = new Box<>();
b.set(42);
int hasil = b.get();
Hasil
Kompilasi berhasil; hasil = 42

Java melakukan boxing dan unboxing untuk int dan Integer.

Cek pemahaman

1. Mana deklarasi generik yang valid?

2. Mengapa menghindari Box tanpa parameter tipe?

Latihan mandiri

Implementasikan Box<T> dengan set(T) dan get(). Buat Box<String> untuk nama menu dan Box<Integer> untuk jumlah.
